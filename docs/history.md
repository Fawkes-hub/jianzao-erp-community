# 关于本仓库的提交历史

## 这是重建的历史，不是原始开发历史

本仓库的历史是**按里程碑重建的技术演进史**：从零建立新仓库，按功能阶段依次导入当时公开范围内的源码快照，逐次提交。它保留了「功能是怎么一层层长出来的」这条可读脉络 —— 底座 → 主数据 → 采购 → 销售 → 库存 → 退货与其他出入库 → 财务与打印 → 订单层 —— 但不携带原始私有开发仓库的 `.git` 对象。

因此：

- 提交时间反映里程碑顺序，**不等同于原始开发的逐日时间线**；
- 提交作者统一为项目发起人，社区贡献在 [CONTRIBUTING.md](../CONTRIBUTING.md) 的 CLA 框架下另行记录；
- 仓库内不含客户沟通、需求评审、内部决策、部署凭据等过程材料；
- 原始开发过程中的技术决策，只以「公开可复用的结论」形式出现在 [docs/](./) 文档中。

**为什么这样做**：原始仓库的历史里夹着私有文档、内部讨论记录与真实部署信息，直接公开会一并带出；筛掉这些内容后，历史本身的价值主要是技术演进脉络，因此用重建的方式保留脉络、丢掉噪声。项目方认为这是比「改写全部历史提交」或「只发一个 0 版本快照」更诚实、也更可控的做法 —— 它不伪装成原始历史。

## 里程碑

| # | 阶段 | 主要交付 |
|---|---|---|
| 1 | 底座 | RuoYi-Vue-Plus 裁剪、TDesign 前端骨架、租户/权限/菜单、Docker Compose |
| 2 | 主数据 | 商品/分类/配比、供应商、客户、仓库、编码序列、Excel 导入导出 |
| 3 | 采购 | 采购入库 + 应付、运杂费分摊、不含税成本、移动加权 |
| 4 | 销售 | 销售出库 + 应收、一单一价、成本快照、毛利 |
| 5 | 库存 | 快照 + 流水 + 期初、条件更新防超卖、库存查询 |
| 6 | 退货与其他出入库 | 采购/销售退货、其他入/出库、撤回与作废 |
| 7 | 财务与打印 | 应收应付台账、收付款核销、结算账户、综合成本、内置送货单/对账单打印 |
| 8 | 订单层 M1 + 模板 | 采购/销售订单分批执行、未交量、变更留痕、自定义打印模板 |

## 后续演进

社区版与商业版共享基础代码。基础进销存的改进在社区版公开推进；商业版功能（生产/委外、盘点、看板、备份、订单层 M2、小程序、SaaS 账户体系）在私有仓库中作为独立增量维护，不进入本仓库。
